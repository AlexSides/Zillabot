# Project Reflection

## Project Reflection Summary

ZillaBot was a multidisciplinary senior design project that required mechanical design, embedded software, electrical integration, testing, and public presentation work. This reflection is based on the public project materials in the repository rather than private team notes.

## What Went Well

- The project produced a visible design progression from early breadboard testing to a 3D-printed enclosed robot.
- The team separated major concerns into subsystems such as navigation, motor control, boundary detection, object detection, PCB/chassis design, and power.
- The repository now includes photos, videos, CAD assets, PCB assets, diagrams, and selected source files, which makes the project easier to understand outside the classroom.
- Telemetry and subsystem testing were used as part of the debugging and validation process.

## Biggest Challenges

- Integrating sensors, motors, power, wiring, and physical packaging into one compact robot was a central challenge.
- Navigation behavior depended on real-world conditions such as floor surface, sensor angle, target distance, and battery/motor response.
- The available records show multiple chassis and code iterations, which suggests that the final system required repeated design changes rather than a single clean build.
- Some performance data was not preserved in a public, measured format, which limits how precisely the final behavior can be summarized here.

## What You Learned

The project demonstrates practical learning in embedded programming, sensor integration, control logic, mechanical packaging, and test-driven iteration. It also shows the value of documenting design decisions as the build changes, especially when a project combines hardware, firmware, and physical competition constraints.

## What You Would Do Differently

- Keep a cleaner public test log with repeated trials, exact conditions, and measured results.
- Preserve labeled photos for each major hardware revision and wiring milestone.
- Create a formal state-transition diagram for the navigation subsystem.
- Separate public portfolio code from private/local configuration files earlier in the project.

## Team and Process Reflection

The public materials identify subsystem ownership across navigation, motor control/power, boundary detection, object detection, and PCB/chassis work. The project required those subsystem efforts to converge into a single robot that could be demonstrated in a competitive setting.

## Future Work

- Include final measured performance data if original logs or reports are recovered.
- Add a formal navigation state diagram and sensor-priority table.
- Add clearer captions for each chassis revision to explain what changed between versions.
- Add a concise bill of materials if public part and cost records are available.

## Closing Note

ZillaBot represents a complete senior design effort rather than a polished commercial product. Its value is in the engineering process: building, testing, redesigning, documenting, and integrating multiple subsystems into a working autonomous robot.
